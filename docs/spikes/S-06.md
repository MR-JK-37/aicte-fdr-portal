# S-06 — OCR engine choice (PaddleOCR vs docTR vs Tesseract)

**Status: PASS (recommendation made); accuracy baseline explicitly deferred to Phase 3 (no documents to test against yet).**

## What was tested
Compared PaddleOCR, docTR (Mindee), and Tesseract (with Indic language packs) on license, current maintenance status, and Hindi/Tamil (Indic) language support, per each project's own current official docs/repo.

## Findings (official sources)

### PaddleOCR
- **License**: Apache License 2.0 (confirmed, GitHub repo `PaddlePaddle/PaddleOCR`).
- **Maintenance**: actively maintained; the GitHub repo description itself ("A powerful, lightweight OCR toolkit that bridges the gap between images/PDFs and LLMs. Supports 100+ languages") and recent ecosystem activity (PaddleOCR-VL, a vision-language variant, announced on Baidu's ERNIE blog) indicate active, current development as of 2026.
- **Indic language support**: documented support for **109 languages** including Hindi (`hi`) and Tamil (`ta`) by language code — directly confirmed.
- **Verdict**: strongest documented Indic coverage of the three, Apache-2.0, actively developed.

### docTR (Mindee)
- **License**: Apache License 2.0 (confirmed, GitHub repo `mindee/doctr`).
- **Maintenance**: repository is **not archived**; shows recent commit activity (repo description states "Ongoing development and maintenance by t2k"; main branch had activity as recently as 2026-10-07/2026-10-04 at time of check).
- **Indic language support**: **could not confirm specific Hindi/Tamil support** from the sources retrieved in this pass — docTR's out-of-the-box recognition models are historically strongest on Latin-script languages; Indic-script support would likely require a custom-trained recognition model, which is a materially larger lift than PaddleOCR's or Tesseract's off-the-shelf language packs. Flag as **unverified/likely weak** rather than confirmed-absent — re-check docTR's model zoo directly (`mindee.github.io/doctr` model zoo page) before ruling it out definitively, but do not plan around unconfirmed Indic support.

### Tesseract (+ Indic language packs)
- **License**: Apache License 2.0 (confirmed).
- **Maintenance**: long-running Google-stewarded project; "offers drop-in models... supports over 100 languages and scripts out of the box" per current sources, including Indic scripts via the `tesseract-ocr-<lang>` traineddata packs (e.g., `hin` for Hindi, `tam` for Tamil) — these are long-established, officially distributed language packs (`tessdata`/`tessdata_best` repos under the `tesseract-ocr` GitHub org).
- **Verdict**: reliable, lightweight, dependable baseline for clean printed text on CPU-only hardware; weaker than PaddleOCR on noisy/handwritten/complex-layout documents (a widely corroborated general finding across the comparison sources, including `koncile.ai`'s PaddleOCR-vs-Tesseract comparison and `reducto.ai`'s 2026 OCR guide), but Indic traineddata packs are mature and well-documented.

## Recommendation
- **Primary: PaddleOCR** — Apache-2.0, actively maintained, explicit documented Hindi + Tamil support (and broader Indic coverage via its 109-language claim), and better general accuracy on real-world scanned/photographed documents (FDRs, bank statements, affidavits are exactly this kind of "imperfect scan" document per CLAUDE.md's description of the product's evidence pipeline).
- **Fallback: Tesseract** — same Apache-2.0 license (no legal friction switching), lighter-weight/simpler deployment (no GPU dependency, smaller footprint), mature official Hindi/Tamil traineddata packs, and a much longer track record — good as a CPU-constrained or air-gapped-environment fallback if PaddleOCR's dependency footprint (PaddlePaddle framework, optional GPU) proves too heavy for the deployment target chosen in Phase 1.
- **Not recommended as primary**: docTR — same license tier as the other two, actively maintained, but Indic-script recognition support could not be confirmed and is the one capability this product specifically needs (Hindi/Tamil FDR and affidavit documents per AICTE's multi-state institution base). Could be revisited later for Latin-script-only sub-tasks (e.g., English-only UTR/reference-number extraction) if a specific accuracy gap with PaddleOCR shows up during the Phase 3 baseline.

## What worked
- License and maintenance-status checks for all three were straightforward and consistent across multiple independent sources.
- PaddleOCR's and Tesseract's Indic support is explicitly, directly documented.

## What did not work
- Could not directly confirm or rule out docTR's Hindi/Tamil model availability from the sources fetched in this pass — this is a genuine gap, not a confident "no." If PaddleOCR turns out to be operationally difficult to deploy, re-check docTR's model zoo explicitly before falling back to Tesseract.

## Deferred to Phase 3 (explicitly, per this spike's scope)
**No accuracy baseline run was performed** — there are no sample FDR/affidavit/bank-statement documents available to test against in Phase 0 (per PREFLIGHT.md §D, authorised sample bank statements and real documents are not yet provided by AICTE). Phase 3 (document vault / OCR pipeline, F-04/F-05) must run PaddleOCR against real or realistically-redacted sample documents before any OCR confidence threshold is hard-coded, consistent with CLAUDE.md rule 2 ("Facts come from the database, never from a model... LLM/OCR output is a candidate with provenance, reviewed by a human").
