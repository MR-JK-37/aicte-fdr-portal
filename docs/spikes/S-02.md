# S-02 — `@expo/ui` Jetpack Compose + SwiftUI coverage

**Status: PARTIAL PASS — coverage confirmed for most components; some need Phase-1 re-verification against the live README before coding; fallback plan recorded.**

## What was tested
Checked `@expo/ui`'s own documentation (npm page, Expo docs `sdk/ui`, GitHub README) for whether it covers the components MASTER_PROMPT §13 requires: lists, forms, sheets, date picker, segmented control, search bar, tabs, large title, dialogs — for both SwiftUI (iOS) and Jetpack Compose (Android).

## What was verified (official sources)
- Package: `@expo/ui`, current version tracks the Expo SDK line — **58.0.22** seen at time of check (npm), consistent with SDK 58.
- Per the Expo blog post "**Expo UI is now stable: SwiftUI and Jetpack Compose from a single import**" (`expo.dev/blog/expo-ui-stable-sdk-56`), Expo UI reached **stable** status as of SDK 56 — it is no longer an "unstable/experimental" API as of the pinned SDK 58, which matters because earlier SDKs shipped it as explicitly experimental.
- Architecture confirmed from the package README (`github.com/expo/expo/tree/main/packages/expo-ui`) and Expo docs (`docs.expo.dev/versions/latest/sdk/ui/`): three tiers —
  1. **Platform tier**: `@expo/ui/swift-ui` and `@expo/ui/jetpack-compose` — one export per native component, 1:1 mapping to the native API (component/prop/event names mirror the native platform).
  2. **Universal tier**: `@expo/ui` top-level — cross-platform components (`Host`, `Column`, `Row`, `Button`, `Text`, `List`, and drop-in replacements for community libraries: BottomSheet, DateTimePicker, Slider, Menu).
  3. **Community drop-in replacements** under `@expo/ui/community/*`.
