# S-07 — Material Symbols packaging on Android (Expo/RN)

**Status: PASS (doc-verified).**

## What was tested
Current official guidance (Google Fonts / Material Symbols GitHub repo) for using Material Symbols as a variable font with tree-shaking in a React Native/Expo Android build, plus the licence file requirement.

## What was verified (official sources)
- **Official repo**: `github.com/google/material-design-icons` — the canonical source for both Material Symbols and the older Material Icons.
- **Format**: Material Symbols is built on **variable font technology** — a single font file combines 2,000+ glyphs with adjustable **variable axes**: `fill`, `weight`, `grade`, `optical size`. This is confirmed directly from Google's Material Design site (`m3.material.io/blog/introducing-symbols`) and the Material Symbols glossary page (`fonts.google.com/knowledge/glossary/material_symbols`).
- **Licence**: Material Symbols (the font files served by Google Fonts and in the GitHub repo) are distributed under the **Apache License, Version 2.0** — confirmed on the repo and on `fonts.google.com`/`developers.google.com/fonts/docs/material_symbols`.
- **Tree-shaking approach for RN specifically**: the `material-symbols` npm package and the `material-symbols-react-native` wrapper (`github.com/guiladg/material-symbols-react-native`) distribute icon definitions as **individual per-icon modules**, so a build only bundles the icons actually imported, rather than shipping the full glyph set. This is the documented tree-shaking mechanism for this ecosystem — "each icon can be imported separately to reduce build size."
- **Variable-axis usage on native (non-web) targets**: standard CSS `font-variation-settings` is a web mechanism; for React Native, the equivalent variable-axis control is more limited — there is an open discussion (`react-native-community/discussions-and-proposals` issue #829) about adding first-class `font-variation-settings` support to React Native's text styling, indicating this is **not yet a fully native, built-in RN API** as of the current RN line. **Practical implication for this repo**: on Android/RN, prefer either (a) pre-rendering/importing specific static icon weights as individual SVG/vector assets per the tree-shaken npm package (avoiding runtime variable-axis manipulation entirely), or (b) if true variable-axis control is required at runtime, re-verify RN's current `font-variation-settings` support directly against the pinned React Native 0.88 (per S-01) release notes before relying on it — do not assume it works without a direct check, since the GitHub discussion suggests inconsistent/partial support historically.

## Recommended approach for this repo
- Package: **`material-symbols`** (npm) for the icon-definition source, consumed through per-icon imports (tree-shaken), rendered as SVG/vector icon components in the Android (Jetpack Compose / RN) build — avoids depending on uncertain RN variable-font-axis support.
- Licence file: ship the Apache-2.0 licence text verbatim from the `google/material-design-icons` GitHub repo's `LICENSE` file (same text as `fonts.google.com`'s stated licence) alongside the icon assets in the repo — e.g. `packages/<mobile-assets>/THIRD_PARTY_LICENSES/material-symbols-APACHE-2.0.txt` — and reference it from the app's licences/attributions screen, consistent with CLAUDE.md's "Material Symbols only for every icon" rule and general open-source attribution hygiene.
- If a later requirement needs runtime weight/fill morphing (e.g., selected-vs-unselected nav icon states using the `fill` axis), re-verify React Native 0.88's current variable-font support before committing to that approach; the documented, safe-today fallback is **shipping multiple static icon variants** (e.g., outlined + filled versions of the same glyph) and swapping components on state change, rather than runtime axis animation.

## What worked
- Licence (Apache-2.0) and canonical source repo location are unambiguous and consistently confirmed across Google's own Fonts site, the Material Design site, and the GitHub repo.
- Tree-shaking approach (per-icon imports) for the npm packaging is directly documented.

## What did not work / needs a build-time re-check
- Could not fully confirm current React Native variable-font-axis support as a reliable runtime mechanism — the open GitHub discussion is suggestive but not a definitive "works/doesn't work" statement for RN 0.88 specifically. **Action item for Phase 1**: before using any runtime `fill`/`weight` axis manipulation on Android, test it directly against the pinned RN 0.88 build; default to the static-variant fallback above if it's unreliable.

## Fallback
Static pre-selected icon variants (outlined/filled pairs, or a small fixed set of weights) swapped via component logic, instead of runtime variable-font-axis manipulation — use if RN 0.88's `font-variation-settings`-equivalent support proves unreliable on Android at Phase 1.
