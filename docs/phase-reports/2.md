## 1. What was built (Modules & Deliverables)

### 1.1 Institution Onboarding & Batch Import (F-02, SPEC §8.5)
- **Representative Onboarding Workflow (`app/institutions/router.py`)**:
  - Implemented application submission (`POST /v1/institutions/onboarding`) with official identity reference and authority document attachments.
  - Added review endpoint (`POST /v1/institutions/onboarding/{id}/review`) with strict separation-of-duties (applicant user cannot approve their own institution onboarding request).
  - Enforced duplicate onboarding conflict prevention (409 Conflict).
- **Batch CSV Import with Provenance (`/v1/institutions/batch-import`)**:
  - Ingests legacy institution records with source file SHA-256 fingerprinting and audit trail logging.
  - Implemented conflict deduplication on existing AICTE codes.
- **Institutions Directory (`GET /v1/institutions`)**:
  - Filterable by AICTE code and name with pagination.

### 1.2 Instrument Register, Immutable Versioning & Blind Index (F-03, SPEC §6.1 / §7)
- **Draft Creation & Lifecycle (`app/instruments/router.py`)**:
  - Draft creation (`POST /v1/instruments/draft`) and updates (`PUT /v1/instruments/{id}/draft`).
  - Optimistic concurrency control via `If-Match` ETag headers against `updated_at`.
  - Stored keyed HMAC-SHA256 blind index column (`instruments.blind_index`) enabling exact-match search without plaintext leakage.
  - Masked instrument identifier serialization (e.g. `••••••••1234`) unless authorized by `VIEW_UNMASKED_IDENTIFIERS`.
- **Immutable Version Snapshots (`InstrumentVersion`)**:
  - Freezes canonical JSON snapshot with SHA-256 content hash upon submission (`POST /v1/instruments/{id}/submit`).
  - Version history endpoint (`GET /v1/instruments/{id}/versions`).
  - Prevents silent overwrites: submitted instruments cannot be modified in place; subsequent edits require formal revision.

### 1.3 Document Vault & Upload Security Pipeline (F-04, SPEC §8.1)
- **Upload Intent & Storage (`app/documents/router.py`)**:
  - Upload intent endpoint (`POST /v1/documents/upload-intent`) issuing presigned upload URLs and quarantine storage keys.
  - Direct upload pipeline (`POST /v1/documents/upload-direct`) executing all security checks synchronously.
- **Security Pipeline (`app/documents/security_scan.py`)**:
  - Magic byte MIME verification verifying genuine PDF and image signatures; rejects disguised files and archive zip bombs.
  - Real ClamAV antivirus scanning over TCP socket (`localhost:3310`) detecting EICAR and malicious payloads.
  - PDF sanitization via PyMuPDF stripping embedded JavaScript, launch actions, and suspicious embedded streams.
  - Content hashing (SHA-256) and perceptual hashing (pHash) for deduplication and duplicate detection.

### 1.4 Observations, Casework & Internal Note Secrecy (F-09, F-25, SPEC §6.3 / §18.1 Scenario 6)
- **Observation Lifecycle (`app/observations/router.py`)**:
  - Full State Machine 3 progression: `OPEN → AWAITING_INSTITUTION → RESPONSE_RECEIVED → UNDER_REVIEW → RESOLVED → CLOSED`.
  - Officer dispatch to institution (`POST /v1/observations/{id}/send-to-institution`).
  - Institution compliance response (`POST /v1/observations/{id}/respond`).
  - Officer resolution with resolution code and reason (`POST /v1/observations/{id}/resolve`).
- **Casework Comments & Internal Note Secrecy (`F-25`)**:
  - Threaded casework comments (`/v1/cases/{case_id}/comments`).
  - Bureau officers can record internal staff notes with `is_internal=True`.
  - Strict secrecy guarantee enforced at both database RLS and application layers: institution users NEVER receive or see internal notes.
  - Attempt by institution users to forge `is_internal=True` is rejected with 403 Forbidden.

### 1.5 Verifiable Cryptographic Submission Receipts (F-20, SPEC §8.1 / §11.1)
- **ReportLab PDF Receipt Generator (`app/receipts/generator.py`)**:
  - Produces official AICTE Regulation Bureau submission receipt with structured metadata, tamper-evident hash prefix, and legal notice disclaimers.
  - Embeds real, high-density QR code containing minimal canonical payload and cryptographic signature.
  - Ed25519 digital signature signing via `app/receipts/signer.py`.
- **Public Verification Endpoint (`GET /v1/public/receipts/verify`)**:
  - Unauthenticated endpoint for public verification of QR payloads against the AICTE root signing key.
  - Rejects tampered receipt IDs, hashes, timestamps, or signatures with 400 Bad Request.

### 1.6 Workload Queues & Role Assignment (F-24)
- **Workload Queues (`app/queues/router.py`)**:
  - Intake Queue (`GET /v1/queues/intake`): aggregates pending onboarding requests and new submissions in `SUBMITTED` / `INTAKE_REVIEW`.
  - Scrutiny Queue (`GET /v1/queues/scrutiny`): displays assigned cases in `SCRUTINY` / `UNDER_SCRUTINY`.
- **Assignment Engine (`POST /v1/queues/assign`)**:
  - Assigns/reassigns cases to specific officers with audit logging and event publishing.
  - Reassignment automatically marks previous assignments as `REASSIGNED`.

### 1.7 Atomic State Machine Engine (SPEC §6.1, §6.3, §7)
- **Central Lifecycle Engine (`app/lifecycle.py`)**:
  - Implemented State Machine 1 (Instrument Lifecycle), State Machine 3 (Observation Lifecycle), and State Machine 7 (Document Lifecycle).
  - Atomic transitions: mutates entity status + writes `StateTransition` + appends `AuditLog` hash chain entry + enqueues `OutboxEvent` in a single database transaction.
  - Database trigger `protect_state_transitions_immutability` strictly prevents UPDATE and DELETE on `state_transitions`.

## 7. Risks & Mitigations
- **Internal Casework Privacy**: Institutional users must never see internal Bureau notes. Mitigated with defense-in-depth: PostgreSQL RLS policy `case_comments_policy` drops internal rows unless `is_bureau_role()`, and application query layer strictly filters `is_internal.is_(False)` for institution callers. Tested by `test_observation_casework.py`.
- **Malware & Zip Bomb Injection**: Malicious files uploaded as evidence. Mitigated via 4-stage pipeline: magic-byte inspection, ClamAV daemon malware scanning, and PyMuPDF sanitization removing active content. Tested by `test_security_scan.py`.
