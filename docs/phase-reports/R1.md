# Stream R1 — Purge simulation and fakes; honest states (2026-10-24)

## Scope actually covered this session
**Web (`apps/web/src`) and mobile (`apps/mobile`): both fully purged and verified.** Backend:
spot-checked, already clean (voice flag defaults off with an honest "not implemented" path, no

## What changed (web)
- **Deleted** `components/SimClockControl.tsx` and `components/VoiceCallModal.tsx` outright
  (not hidden, not renamed).
- **`App.tsx`**: removed all fabricated state — the hard-coded 4-instrument array
  (`AXIS-FDR-99201` etc.), the fabricated SHA-256 audit-chain entries (including a
  `Math.random()`-based fake hash generator in `handleAddAuditEntry`), the sim-clock state
  (`simClockDate`/`simOffsetDays`/`handleSetOffset`/`handleAdvanceClock`), the voice-call modal
  wiring, and the footer's marketing tech chips ("PostgreSQL 16 + pgvector", "Sarvam AI +
  Pipecat", etc.). `instruments` is now a real (empty) `useState<Instrument[]>([])` with a comment
  explaining why it's empty and what wires it up (stream R2 auth + R3 data).
- **`VerificationView.tsx`** (617→~250 lines): removed "Simulate Statement Ingestion", "Simulate
  L2 Reply", the `setTimeout`-faked reconciliation success, and every hard-coded bank/UTR table row

  from the `instruments` prop). Replaced with honest "not yet connected to the API" states per

  is selected (empty state when none).
- **`NewFDRSubmission.tsx`**: removed the entire fake OCR pipeline (`handleSimulatedUpload`

- **`AuditLogView.tsx`**: removed the entire fake hash-chain UI (per-block "Simulate Tamper"
  toggle, the static "Chain Integrity: 100% Valid" claim). Replaced with an honest note
  distinguishing the real `make audit-verify` script (works today, runs directly against the DB)

- **`AdminConsoleView.tsx`**: removed every hard-coded `status: 'healthy'` connector
  (core-banking/PFMS/DigiLocker/FCM/APNs all claimed healthy with fake latencies), the fake

## Carried forward — explicitly NOT done this session
1. **Navbar role `<select>`** (`apps/web/src/components/Navbar.tsx`) — left in place deliberately.
   R2.4 removes it as part of wiring real server-driven navigation (`GET /v1/me/navigation`);
   removing it now without that would leave the app with no way to change the acting-role
   demonstration state at all, which is a worse interim state for continued R1/R3 work than one
   known, tracked `forbidden-strings` hit.
2. **`forbidden-strings` is not yet a `make verify` gate** — see above; wiring it in now would make
   `verify` permanently red for a single known, already-tracked, next-phase item (the role
   switcher), which isn't useful signal. Wire it in once R2 removes that switcher.
3. **L0–L3 evidence-level data model** (CLAUDE.md non-negotiable #3: "never collapse into one
   score"). The backend (`app/models/enums.py::EvidenceLevel`) and the web client's `types.ts`
   both still model evidence as **one ordinal enum field**
   (`L0_DECLARED`/`L1_EXTRACTED`/`L2_BANK_CONFIRMED`/`L3_LEDGER_RECONCILED`) rather than the spec's
   separate attributes (Declared / Document-extracted / Bank-confirmed / Ledger-reconciled /
   Inconclusive-Rejected). This is a real schema migration (new columns/table, service-layer
   changes, every consumer updated), not a UI relabel — out of scope for this session. UI copy was
   softened where it appeared in deleted/rewritten screens to stop implying a single "verified"
   score, but the underlying model change is still open. Track for R1 continuation or R4.
4. **Real biometric/PIN app lock** (`apps/mobile/src/components/BiometricLockModal.tsx`) — the
   fake always-succeeds unlock was removed (purge), but building the real
   `expo-local-authentication`-backed version is a new feature, not a purge; tracked for R6 (M-03).
